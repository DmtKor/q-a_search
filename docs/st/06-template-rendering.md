## Цель
Реализовать безопасный и предсказуемый рендеринг `cases.response_template` с использованием Go `text/template` и входного `user_context`.

## Границы модуля
Модуль не знает ничего про БД или HTTP. Он предоставляет библиотечный компонент:
- компиляция/кэш шаблонов (опционально)
- рендер в строку
- ограничения (лимиты)

## Требования (обязательные)
- Устойчивость к отсутствующим полям контекста:
  - шаблоны должны не падать при missing keys (нужно выбрать режим/подход, например использовать `map` и безопасные helper-функции)
- Контекст: `user_context` — произвольный JSON object (после decode → `map[string]any`).
- Безопасность:
  - использовать `text/template` (не `html/template`, т.к. отдаём plain text)
  - ограничить func map (не подключать опасные/ненужные функции)
- Лимиты:
  - ограничение на размер результата (например max N символов; точное значение зафиксировать в конфиге/константе)
  - ограничение на размер входного `user_context` (по желанию, через API-layer)

## Интерфейс
- `Render(ctx, tpl string, userContext map[string]any) (string, error)`

Ошибки:
- синтаксис шаблона → `validation_error` на уровне API (модуль 03 при сохранении кейса) или `internal_error` на уровне Search, если шаблон “сломался” после импорта.

## Уточнения (решения по открытым вопросам)

1. **Поведение при отсутствующих полях** — **Вариант A:** передавать в шаблон обёртку над `user_context`, которая при обращении к отсутствующему ключу возвращает пустую строку (без паники). От авторов шаблонов не требовать везде писать `default`.

2. **Состав func map** — Минимальный безопасный набор: без exec, eval, доступа к файлам/сети. На первом этапе достаточно подстановки полей (`{{.name}}`); при необходимости добавить `default`, `eq`, `and`, `or`, `not`, `len`, при желании `printf`. Форматирование даты, обрезка строки и т.п. — позже, если понадобятся в кейсах.

3. **Лимит длины результата** — По умолчанию **32_000 символов** (константа в пакете). Возможность задать лимит при создании рендерера (опция в конструкторе). Конфигурация — так и задумано.

4. **Кэш шаблонов** — Первая версия **без кэша**: каждый вызов `Render` — `template.New().Parse(tpl).Execute`. Кэш и инвалидация — позже при необходимости.

5. **Интеграция с Search** — Реализовать тип в `internal/template`, удовлетворяющий интерфейсу из Search; в Glue подставить его в search.Service. Изменений в `internal/search` не требуется.

6. **Cases (03)** — В рамках 06 только рендерер. Валидацию шаблона при сохранении кейса (например, пробный Render с пустым/тестовым контекстом) оставить на усмотрение модуля 03; в 06 не входить.

## Тесты
### Unit
- рендер при неполном контексте (missing fields) не падает
- корректный рендер простых шаблонов
- лимит длины результата срабатывает предсказуемо
- некорректный шаблон возвращает понятную ошибку

## Критерии приёмки
- Search (02) и Cases (03) могут использовать один и тот же компонент рендера.

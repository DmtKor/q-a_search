## Цель
Реализовать безопасный и предсказуемый рендеринг `cases.response_template` с использованием Go `text/template` и входного `user_context`.

## Границы модуля
Модуль не знает ничего про БД или HTTP. Он предоставляет библиотечный компонент:
- компиляция/кэш шаблонов (опционально)
- рендер в строку
- ограничения (лимиты)

## Требования (обязательные)
- Устойчивость к отсутствующим полям контекста:
  - шаблоны должны не падать при missing keys (нужно выбрать режим/подход, например использовать `map` и безопасные helper-функции)
- Контекст: `user_context` — произвольный JSON object (после decode → `map[string]any`).
- Безопасность:
  - использовать `text/template` (не `html/template`, т.к. отдаём plain text)
  - ограничить func map (не подключать опасные/ненужные функции)
- Лимиты:
  - ограничение на размер результата (например max N символов; точное значение зафиксировать в конфиге/константе)
  - ограничение на размер входного `user_context` (по желанию, через API-layer)

## Интерфейс
- `Render(ctx, tpl string, userContext map[string]any) (string, error)`

Ошибки:
- синтаксис шаблона → `validation_error` на уровне API (модуль 03 при сохранении кейса) или `internal_error` на уровне Search, если шаблон “сломался” после импорта.

## Тесты
### Unit
- рендер при неполном контексте (missing fields) не падает
- корректный рендер простых шаблонов
- лимит длины результата срабатывает предсказуемо
- некорректный шаблон возвращает понятную ошибку

## Критерии приёмки
- Search (02) и Cases (03) могут использовать один и тот же компонент рендера.

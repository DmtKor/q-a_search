1. Описание проекта

Проект представляет собой систему управления базой знаний с гибридным поиском (семантический + полнотекстовый) на базе PostgreSQL + pgvector. Система позволяет хранить структурированные "кейсы" (вопросы/ответы с категориями, ключевыми словами и шаблонами ответов), выполнять поиск по ним с ранжированием, а также обрабатывать "тикеты" — запросы, на которые система не смогла найти уверенный ответ. В проекте реализована MVP-версия: сырая, но с работающим основным функционалом: CRUD кейсов, гибридный поиск, система тикетов, конвертация тикетов в кейсы, управление приложениями (мультитенантность), рендеринг шаблонов ответов, метрики запросов и демо-интерфейс.

3. Запуск проекта

1) Запустить PostgreSQL с pgvector:
   docker run -d --name pgvector-test -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=kb -p 5432:5432 pgvector/pgvector:pg16

2) Запустить API-сервер (из корня проекта):
   export DATABASE_URL="postgres://postgres:postgres@localhost:5432/kb?sslmode=disable"
   export AUTH_SECRET="dev-secret-change-in-production"
   go run ./cmd/api

3) В другом терминале создать staff-токен:
   go run ./cmd/seed-token
   (выведет значение токена: local-staff-token)

4) Запустить демо-интерфейс:
   cd web && npm install && npm run dev
   Открыть http://localhost:5173, ввести токен и базовый URL API (http://localhost:8080) в Настройках.

Проверка работоспособности:
- Перейти в раздел "Кейсы", создать кейс, перевести его в pending_review, затем в approved
- Перейти в раздел "Поиск", ввести запрос, убедиться, что поиск возвращает результаты
- Если confidence ниже порога — в разделе "Тикеты" появится тикет

4. Демонстрация работы проекта

1) Страница входа/настроек — ввод Bearer token и базового URL
2) Список кейсов (База знаний) — пустой список после запуска
3) Создание нового кейса — форма создания с полями (категория, заголовок, вопросы, ключевые слова, шаблон ответа)
4) Детальная страница кейса — просмотр созданного кейса
5) Смена статуса кейса на pending_review, затем на approved
6) Страница поиска — ввод поискового запроса, отображение результатов (chunks)
7) Список тикетов — отображение созданного тикета (если поиск дал низкий confidence)
8) Детальная страница тикета — просмотр и обработка тикета
9) Конвертация тикета в кейс
10) Список приложений — управление приложениями
11) Настройки приложения — изменение порога confidence и top_k
12) Импорт/экспорт кейсов
